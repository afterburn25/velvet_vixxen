## Behavior

Owners can schedule an immutable saved Hero or Visual Footer draft with a start and optional end. The explicit end policy keeps the scene live or restores the preceding publication. One open schedule per section avoids overlapping rollback rules. Draft edits remain independent. Manual Publish or Restore supersedes pending automatic changes. Schedule dates and current states appear in the owner publishing calendar.

The responsive **Site & Design → Scene schedules** page supplies creation, cancellation, recent outcomes and **Run due scenes now**. The Composer **Schedule** button saves drafts and opens the selected section. An installed-site command, `app/Console/run_scenes.php`, supports a host-configured periodic runner. No public request or calendar read executes the worker.

Storage uses existing settings and scene records without a migration. File writes share the existing atomic data-store mutation lock. MySQL section settings rows serialize scene writes inside transactions. A processing claim commits before work; publication, version history and completion commit atomically from fresh locked state. The 60-second claim lease supports interruption recovery. The worker rechecks current owner authority, saved publication identity, immutable content and timing before mutation. A complete missed window is skipped, and newer manual work is preserved.

All seven existing required CI jobs remain. New source, actual-package file/MySQL HTTP and real desktop/mobile browser producers extend the retained gates.
