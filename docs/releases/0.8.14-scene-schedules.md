## Owner workflow

Open **Site & Design → Scene schedules**, choose **Homepage Hero** or **Visual Footer**, and schedule a saved draft with a required start and optional end in the displayed site timezone. The Composer **Schedule** button saves both drafts and opens the selected section. Each section supports one open schedule; finished outcomes retain the latest 20 records.

The schedule stores a fixed scene snapshot. Later draft edits do not change it. Choose to keep the scheduled scene live or return to the preceding publication after the end. An automatic activation or return preserves the current editor draft. Manual Publish or Restore supersedes that section's automatic change. Cancelling an active schedule keeps the current live composition and cancels its automatic return.

The publishing calendar shows saved start/end dates and actual states. Opening the editor, calendar or public page does not execute the worker. Use **Run due scenes now**, or configure hosting cron to run `php /path/to/website/app/Console/run_scenes.php --limit=10`. The CLI accepts limits 1–25; the release does not configure or verify the customer's hosting cron. Changes occur when the runner checks them, and a completely missed start/end window is skipped.

## Storage and correctness

The implementation uses existing settings and scene records on both file and MySQL storage; no migration is added. A shared section lock serializes manual and automatic scene mutations. A durable processing claim precedes work; publication, scene history and completion commit atomically. An interrupted claim can be recovered after its 60-second lease. Bounded file-lock waiting avoids a spurious failure when two workers start together; a busy section stays intact for the next check.

Every worker phase validates saved schedule/claim/snapshot data and rechecks the creator's current owner authority. Production time is sampled after waiting for locks. Stale schedule, draft, publication and timezone revisions are refused. Invalid or skipped/repeated local daylight-saving times are rejected, and saved instants remain fixed in UTC. A revoked creator's work is held without publication and cannot revive when their authority later returns. Draft-only file scenes remain private until actually published.
