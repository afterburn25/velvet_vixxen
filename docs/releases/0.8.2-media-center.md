## Scope

- Advance the visible release version with completed work, as explicitly directed by the user. Keep the canonical version, running labels, installer stamps, checkout metadata and package compatibility consistent. Preserve historical release fixtures and identities.
- Save exactly the retained gallery photographs in their intended order. Expose caption and shared asset-tag fields, mobile ordering, unsaved removal undo, cover fallback and consistent free-preview positions.
- Save playlist track order and preserve or deliberately clear scheduling dates. Reject missing or stale gallery/playlist form revisions, invalid IDs, repeated items, oversized metadata and invalid dates before the saved collection changes.
- Use one common file-store lock and compare the first read before ordinary writes. Apply gallery, photo-tag and playlist changes atomically in fresh file data or real MySQL transactions. Use strict stored-data handling and unique temporary files.
- Publish bounded due media through the owner/CSRF-protected action or explicit CLI. Preserve access and dates, hold later publish dates, avoid duplicate transitions and keep ordinary GET requests read-only.
- Check playlist access before exposing a public playback queue and retain individual track access/preview checks. Preserve existing membership-tier rules when ordinary media forms omit plan fields; fix and independently exercise the inherited MySQL rule-insert quoting error.
