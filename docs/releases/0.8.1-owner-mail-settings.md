## Scope and owner behavior

The active owner can now open **System → Email & SMTP** in the existing admin shell and configure Disabled, SMTP or PHP mail delivery. The page includes sender details, SMTP connection/security/credentials, the saved mode, readable transport status and links to campaigns and communication preferences. It preserves the existing neon pink/magenta/black interface and category navigation. See [the owner guide](../EMAIL_SETTINGS.md).

Saving never sends email. A blank password retains the saved credential; a separate explicit control clears it. The safe snapshot contains only editable public settings, a password-present flag and a configuration revision. The saved password is never echoed into HTML.

A valid explicit From address wins. When From is blank, a valid email-shaped SMTP username precedes the current owner fallback. Runtime and installer reject unsafe header controls before normalization while accepting ordinary pasted address forms, including Gmail and plus-address forms. SMTP validation covers hostname/IP, port and security mode; connection errors expose safe status information rather than raw provider responses.

The owner test uses saved settings and a fixed plain-text diagnostic addressed only to the current owner account. It consumes a one-use, revision-bound token before sending, enforces a 60-second per-session cooldown, releases the session during network work and rechecks the active owner and configuration immediately before SMTP DATA. It cannot be used to submit arbitrary recipient/content, and it does not create a member outbox item. Accepted, failed, unknown and cancelled outcomes remain distinct. Unknown acceptance is not automatically retried. Saving clears the previous result; a result whose configuration revision is stale is hidden.

## Security and configuration preservation

GET and POST require the current stored account to remain active and an owner; a stale owner role in the session is insufficient. Actions enforce POST and CSRF. Settings are not cached in the owner response. A keyed revision covers the full configuration; a nonblocking lock and fresh read precede a mail-only merge, preserving unknown mail keys and unrelated settings. Stale or unsafe input leaves the saved configuration unchanged.

Storage remains compatible with the existing protected plaintext configuration and `.previous` backup. No encrypted-credential migration is claimed. Installed configuration, keys, backups, credentials, private records and logs remain outside source control and customer packages. Normal audit metadata contains fixed non-sensitive results rather than passwords or provider diagnostics.
