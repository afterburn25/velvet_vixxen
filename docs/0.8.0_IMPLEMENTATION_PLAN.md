# 0.8.0 — Marketing, Publishing & Analytics Implementation Plan

## Baseline

- Runtime baseline: `0.7.1`
- Working branch: `feature/0.8.0-marketing-publishing-analytics`
- Tracking issue: `#9`
- Public installation package remains runtime-only.

The 0.7.1 ownership-safe installer hotfix is part of the baseline. The next runtime package must preserve automatic repair for panel-owned `config`, `storage`, `uploads`, `database/backups`, and add-on runtime directories without using mode `0777`.

## Product goals

0.8.0 adds a complete editorial and marketing layer without flattening the website into static graphics. Public navigation, article text, forms, campaign CTAs, membership gates, analytics consent, and commerce links remain live HTML and server-side application behavior. Canva remains optional artwork tooling.

## Scheduled task runner

A live operational runner is required in the runtime package:

```text
scripts/run_marketing_tasks.php
```

It will process:

- Scheduled post publication and expiration
- Banner activation and expiration
- Visual Composer scene changes
- Newsletter recipient batches
- Automated email queueing
- Analytics rollups
- Retention cleanup

The task must be idempotent, lock-aware, resumable, and safe to invoke repeatedly from cron.

## Security requirements

- Owner-only editorial and campaign mutation
- CSRF validation on every state-changing form/API
- Preview tokens are high entropy, scoped, and expiring
- Subscriber import validates and normalizes email addresses
- Unsubscribe links use signed, single-purpose tokens
- Suppression records override all campaign segments
- Segment queries use prepared database access
- Email variables are escaped by context
- Campaign redirects reject unsafe URL schemes
- Analytics endpoints rate-limit and validate event names and payload sizes
- CSV exports prevent formula injection
- No private communication data enters marketing templates or analytics payloads

## Runtime-only ZIP policy

Include only operational site files, migrations, assets, default templates, writable directories, and these required live runners:

- `scripts/run_billing.php`
- `scripts/run_addon_tasks.php`
- `scripts/run_marketing_tasks.php`

Exclude:

- `.git`, `.github`
- `/docs`, `/tests`
- project status, roadmap, handoff, and contribution files
- test reports and screenshots
- SDK source
- test/demo/build/cleanup scripts
- development schema snapshots
