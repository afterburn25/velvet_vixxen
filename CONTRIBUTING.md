# Contributing to Velvet Vixxen

## Branch and evidence rules

- `main` is last-known-good.
- Use a focused `feature/*` or `fix/*` branch.
- Do not claim merge or green CI without checking the live repository.
- Keep packaged-release status separate from repository status.

## Required local checks

```bash
bash scripts/clean_runtime.sh
bash scripts/test.sh
bash scripts/test_http.sh
bash scripts/clean_runtime.sh
php tests/Security/repository_safety.php
```

Run disposable MySQL and applicable Playwright suites when the environment permits. Document unavailable checks rather than marking them passed.

## Add-on contributions

- Do not modify core files for optional features.
- Use the 0.6.x extension APIs and starter add-on.
- Include a valid `addon.json`, semantic version, compatibility range, documented permissions, checksums, README, changelog, and tests.
- Commercial packages should use an Ed25519 signature generated by a protected signing process.
- Never include private keys, `.env`, credentials, customer data, or private media.
- Add-on migrations need add-on-specific table names and reversible `down` operations.
- Test install, activate, deactivate, update, rollback, preserve-data uninstall, purge uninstall, dependencies, conflicts, quarantine, and safe mode.

## General safety

- PHP 8.2+ compatible
- Prepared database operations
- CSRF on authenticated writes
- Escaped output and validated uploads
- Protected originals outside public paths
- No raw payment-card storage
- Never mode `0777`

Update status, handoff, roadmap, changelog, and exact test evidence for release-sized changes.
